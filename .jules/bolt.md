## 2023-10-27 - [Client-Side Data Caching]
**Learning:** Redundant API calls were being made on Next.js client-side navigations (e.g., across pages) due to components relying on the custom `useApi` hook that refetched data on every mount. Since the architecture favors client-side fetching with Supabase, an in-memory SWR (Stale-While-Revalidate) caching mechanism is necessary to keep navigation instantaneous and minimize database load.
**Action:** Enhance the `useApi` hook to support an in-memory `apiCache` Map via a `cacheKey` parameter. When a `cacheKey` is provided, `useApi` will instantly initialize with cached data if available (preventing layout shifts and redundant hard-loading states) while fetching updated data in the background. Apply this `cacheKey` to frequently mounted hooks across pages (like `/buy`, `/rent`, `/agents`).
