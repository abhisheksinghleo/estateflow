## 2026-07-16 - [Preserving Framer Motion on Next.js Images]
**Learning:** When migrating from a native `<img>` tag with framer-motion (e.g. `<motion.img>`) to Next.js `<Image fill />`, the Next.js `<Image>` component cannot be wrapped as `<motion.Image>` directly or it might cause issues or lose optimizations. In addition, using `<Image fill />` makes the image absolutely positioned, which means sibling elements like overlays or badges will be covered unless explicitly given a higher `z-index` (like `z-10` or `z-20`).
**Action:** Always wrap the Next.js `<Image>` in a `position: relative` container that handles the Framer Motion animation (e.g., `<motion.div className="relative h-full w-full">`). Ensure sibling components sharing the same parent container are updated with appropriate `z-index` classes to remain visible.
