## 2024-05-16 - SWR Cache Invalidation & React State Synchronization in `useApi`
**Learning:** When implementing or modifying cache invalidation in the `useApi` hook, relying on truthiness of initial data (like `!initialData`) to determine the `loading` state causes bugs when fallbacks are valid truthy empty arrays. Also, adding `fallback` to `useEffect` or `useCallback` dependency arrays causes infinite render loops because call sites often pass inline array literals (e.g., `[]`).
**Action:** Always ensure the React state is fully synchronized during render. Use explicit cache presence checks (e.g., `apiCache.has(cacheKey)`) rather than checking data truthiness. When managing dynamic route changes, derive state from props during render (`if (cacheKey !== currentCacheKey)`) to avoid unmounting components, and exclude `fallback` from dependency arrays.
