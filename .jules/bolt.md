## 2024-05-24 - SWR Cache Loading State & Dynamic Routes Bug
**Learning:** When implementing an SWR cache in a hook like `useApi`, relying on initial data (e.g., `!initialData`) to determine the `loading` state causes bugs when fallbacks are valid truthy empty values (like empty arrays `[]`). Additionally, Next.js dynamic routes can update the hook's `cacheKey` prop without unmounting the component, leading to stale cached data and incorrect loading states being displayed if state is only initialized on mount.
**Action:** Use explicit cache presence checks (`apiCache.has(cacheKey)`) for determining loading states, and derive state from props during render (e.g., `if (cacheKey !== currentCacheKey)`) to synchronize the internal hook state with external key changes without needing a full re-mount.
