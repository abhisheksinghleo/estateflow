## 2024-07-22 - Framer Motion and Next.js Image Component Integration
**Learning:** When replacing a native `<motion.img>` with the Next.js `<Image>` component in this architecture, directly animating `<motion.img>` or `<Image>` can result in broken animations and layout issues, especially when utilizing Next.js `fill`. Furthermore, the sandbox's lack of internet access causes external images to fail local Next.js image optimization (500 errors). Sibling elements (like badges and overlays) positioned absolutely within the same container can become hidden behind the Image component.
**Action:** Always wrap the Next.js `<Image>` component within a `<motion.div>` (e.g. `<motion.div className="relative h-full w-full">`) to preserve Framer Motion animations. Add the `unoptimized={true}` prop to the Next.js `Image` for external URLs to bypass the local sandbox optimization failures. Ensure that sibling elements have explicit z-index classes (e.g., `z-10`, `z-20`) to remain visible over the absolutely positioned Next.js Image.
## 2024-07-22 - Re-evaluating Performance Optimizations and Sandbox Limitations
**Learning:** Adding `unoptimized={true}` to a Next.js `<Image>` component entirely negates the performance benefits of using Next.js Image (LCP improvement, bandwidth reduction via modern formats and resizing). While it might be required for external images in a sandbox without internet access (to prevent 500 errors), it shouldn't be claimed as a performance improvement. Furthermore, complex client-side filtering and sorting in React components (like traversing an array with multiple conditional checks) can block the main thread unnecessarily on every render if not memoized.
**Action:** When constrained by the sandbox's lack of internet access preventing local Next.js image optimization, avoid Next.js Image migrations for external sources if the primary goal is a performance PR. Instead, find measurable performance improvements in other areas, such as using `useMemo` to memoize expensive client-side operations (like array filtering and sorting) to reduce unnecessary CPU cycles during re-renders.
