## 2024-05-17 - React State Sync for Dynamic Route Changes
**Learning:** When implementing or modifying cache invalidation in the `useApi` hook, the React state must be fully synchronized during render. Also, explicit cache presence checks (`apiCache.has(cacheKey)`) are required instead of relying on `!initialData` to determine the `loading` state to avoid bugs when fallbacks are empty arrays. Furthermore, dynamic route changes without unmounting components require deriving state from props during render (e.g. `if (cacheKey !== prevCacheKey)`) to properly sync the state.
**Action:** When implementing similar hooks that handle caching, make sure to sync state during render for dynamically changing props without unmounts, use strict cache presence checks, and do not add `fallback` to dependency arrays for hooks as callers often pass inline literals.
