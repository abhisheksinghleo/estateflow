## 2024-05-31 - [In-Memory API Caching via Custom Hook]
**Learning:** When implementing an in-memory cache in custom React hooks like `useApi`, ensuring that the returned `refetch` function explicitly bypasses the cache (e.g. by passing `{ force: true }`) is critical, otherwise existing calls to `refetch()` without arguments will mistakenly return the cached hit instead of fetching fresh data. Furthermore, to properly handle dynamic route changes without unmounting components, the `cacheKey` updates must be managed by deriving state from props during render. Also, use explicit cache presence checks (`apiCache.has(cacheKey)`) rather than relying on initial data to avoid bugs with fallbacks like empty arrays. Finally, early returns in `fetch` prevent background SWR network calls.
**Action:** Always implement a `{ force: true }` bypass in cache-enabled refetch mechanisms and manage state deriving properly during render.
