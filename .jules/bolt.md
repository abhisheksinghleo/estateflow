## 2024-05-27 - [useApi Cache Invalidation & React Synchronization]
**Learning:** Client-side API fetching was centralized in `useApi`, leading to redundant background network fetching on component mount or navigation, heavily impacting page load times. Simply relying on SWR-like background fetches isn't enough to prevent the network request.
**Action:** When implementing or modifying an in-memory cache in the `useApi` hook, the `fetch` function must include an early return on a cache hit. During render, React state must be synchronized to avoid issues, using `apiCache.has(cacheKey)` for initial `loading` state rather than relying on `!initialData`, preventing bugs when fallbacks are empty arrays. Furthermore, dynamic route changes require carefully tracking `prevCacheKey` to update state on the fly without full unmounting.
