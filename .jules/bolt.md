## 2025-02-18 - Client-Side Caching SWR with initial fallback and dynamic state
**Learning:** When adding cache invalidation and Stale-While-Revalidate pattern manually in React custom hooks inside Next.js 13/14 App Router (e.g. `useApi`), passing cacheKey dynamically for derived states on route change can cause initial loading state true overriding existing fallback truthy checks when empty fallback arrays get mistakenly rendered as no cache hit. SWR Sates derived natively bypassing initial effect on data hit prevent extra renders and SWR can be kept seamless on components like Dashboard or Filters.
**Action:** Always maintain truthy empty checking arrays (`!apiCache.has(cacheKey)`) as explicit presence when deriving initial caching state on components rather than implicit (`!initialData`) fallback arrays to decide SWR caching loading behaviors on custom implementations and do cache checks before resetting states.
