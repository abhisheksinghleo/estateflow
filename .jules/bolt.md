## 2024-05-20 - React State Synchronization for Caching
**Learning:** When implementing cache invalidation in hooks like `useApi`, relying on initial data checks (e.g. `!initialData`) to determine loading state is flawed when fallbacks can be truthy but logically empty (like `[]`). Furthermore, dynamic route changes can cause incorrect data to persist if state isn't explicitly re-synchronized with `cacheKey` changes during render.
**Action:** Always fully synchronize React state during render using explicit cache presence checks (`apiCache.has(cacheKey)`) rather than truthy checks, and derive state from props to handle dynamic route changes without unmounting. Avoid adding `fallback` to `useEffect` dependency arrays, as inline array literals will cause infinite render loops.
