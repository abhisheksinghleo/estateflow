## 2024-05-24 - Next.js Image Integration with Framer Motion and onError Fallbacks
**Learning:** When replacing native `<img>` tags with Next.js `<Image>`, integrating with Framer Motion requires wrapping the `<Image>` in a `<motion.div>` rather than using `<motion.img>`, as Next.js's wrapper conflicts with direct motion application. Additionally, when migrating an `onError` fallback handler to `<Image>`, the browser prioritizes the automatically generated `srcset` over the `src`. Thus, to ensure the fallback image displays, `e.target.srcset` must be explicitly cleared (e.g., `e.target.srcset = ""`) in the error handler. Finally, when using `<Image fill />`, the immediate parent must have a positioned layout (e.g., `position: relative`) to prevent the image from expanding unexpectedly.
**Action:** Always wrap Next.js `<Image>` components inside `<motion.div>` for animations, clear `e.target.srcset` in `onError` handlers, and ensure the parent element has `relative` positioning when using `fill`.
