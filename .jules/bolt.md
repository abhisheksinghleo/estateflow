## 2024-05-18 - Next.js Image with Framer Motion and Error Fallbacks
**Learning:** When migrating from native `<img>` to Next.js `<Image>`, applying Framer Motion animations directly to the image (e.g., `<motion.img>` to `<motion.Image>`) can be problematic, particularly because `<Image fill>` requires a parent container with positioned layout. Furthermore, handling image errors via direct DOM mutation (e.g., `e.target.src = ...`) is an anti-pattern in React and can cause issues with Next.js's optimized image rendering. The local environment's lack of internet access makes proper fallback handling critical for verification.
**Action:** When animating Next.js `<Image>`, wrap it in a `<motion.div>` that has `className="relative"` and appropriate dimensions. Handle image loading errors by using a React state variable (e.g., `imgError`) toggled via the `onError` prop, and compute the final image source based on this state. Always reset the error state via `useEffect` when the source prop changes to avoid stale state. Ensure sibling elements (like absolute badges) have explicit `z-index` classes to prevent them from being obscured by the `<Image fill>` component's absolute positioning.
